# Cost & Latency Engineering for Long-Running LLM Agents

*Figures verified against primary provider docs and engineering blogs. Anthropic/DeepSeek page footers read © 2026; the Gemini caching doc reads "last updated 2026-09-10". Prices change — check live pages.*

## 1. Prompt caching by provider

**Anthropic** ([docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)) offers *automatic* caching (one top-level `cache_control`; the breakpoint auto-advances to the last cacheable block each turn) and *explicit* block-level breakpoints. **Max 4 breakpoints**; a 5th returns HTTP 400. Breakpoints are free — you pay only for what is written and read. Default TTL is **5 minutes, refreshed free on every hit**, measured from the *start* of the reading/writing request, so generation time counts against it (a 4-minute stream leaves ~1 minute). A **1-hour TTL** costs **2× base input** vs **1.25×** for 5-minute writes.

Mechanics: `cache_control` writes exactly **one** entry — the cumulative prefix hash through that block — and reads walk backward up to a **20-block lookback window**. Writes happen *only* at breakpoints, so the lookback "does not find stable content behind your breakpoint; it only finds entries that prior requests already wrote." A timestamp on the last block means the hash never matches: you pay a fresh write every request and never get a read. Pricing: Sonnet 4.6 is $3/MTok base → $3.75 write-5m → $6 write-1h → **$0.30 read** (0.1×); Opus 5 $5/$6.25/$10/$0.50; Haiku 4.5 $1/$1.25/$2/$0.10. Fable 5.1/Mythos 5.1 read at **0.025×**. **Minimum cacheable prompt**: **512** tokens (Fable/Mythos 5.x, Opus 5), **1,024** (Opus 4.8, Sonnet 5, Sonnet 4.6/4.5), **2,048** (Opus 4.7, Haiku 3.5), **4,096** (Opus 4.6/4.5, Haiku 4.5). Below minimum, caching is silently skipped.

Invalidation follows `tools` → `system` → `messages`; a change kills that level *and everything after* ([table](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#what-invalidates-the-cache), [tool-use page](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching)). **Tool-definition changes invalidate the entire cache.** Web search/citations/`speed` toggles kill system+messages. `tool_choice`, images, thinking params, and `effort` kill messages. `defer_loading` + tool search *preserves* cache: discovered tools append as `tool_reference` blocks inline in history. Server-tool results get an automatic 5-minute breakpoint. Anthropic also supports **pre-warming** via `max_tokens: 0`, and mid-conversation `{"role":"system"}` messages that don't invalidate the prefix (Opus 5/4.8, Fable/Mythos; not Sonnet 5).

**Context management** ([editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [compaction](https://platform.claude.com/docs/en/build-with-claude/compaction)): `clear_tool_uses_20250919` clears oldest tool results at a `trigger` (example 30,000 tokens), keeping `keep: 3` recent, with `clear_at_least` (example 5,000) and `exclude_tools`. Anthropic states plainly that tool-result clearing **invalidates cached prefixes**, so `clear_at_least` exists "to make the cache invalidation worthwhile"; keeping thinking blocks preserves cache. Server-side compaction (`compact_20260112`) defaults to a **150,000-token trigger** (floor **50,000**); SDK compaction defaults to **100,000**.

**OpenAI** ([docs](https://developers.openai.com/api/docs/guides/prompt-caching)) caches automatically. On **GPT-5.6+**: writes **1.25×**, reads **0.1×**, minimum **1,024 visible tokens** (hidden system content excluded), TTL **`30m`**, up to **4 cache writes**/request. OpenAI's framing: one write + one full reuse = **1.35×** vs **2×** uncached; one write + nine reads = **2.15×** vs **10×**. Earlier models have **no write charge**; `prompt_cache_retention` gives `in_memory` (≈5–10 min idle, ≤1h) or `24h` (≈30 min typical, ≤24h; default without Zero Data Retention), and cached tokens round down to **×128**. Cached state is **per-machine**; traffic above **~15 req/min** can overflow-route, so `prompt_cache_key` steers related requests together (pre-5.6), ~15 req/min per key. Reported outcomes: **~70%** hit rate for a single-turn judge, **>90%** for a multi-turn agent with a breakpoint after each tool result. Two documented traps: the **minimum-length cost trap** (break-even $L = M(r + \frac{w-r}{N})$ — at M=1024, r=0.1, w=1.25 that is 102.4 + 1177.6/N, so a 103-token prefix needs ≥1,963 requests to justify expanding to 1,024), and switching implicit→explicit mode, which cannot see the implicit breakpoint's stored entry.

**DeepSeek Context Caching on Disk** is default-on ([guide](https://api-docs.deepseek.com/guides/kv_cache), [launch post 2024-08-02](https://api-docs.deepseek.com/news/news0802), [pricing](https://api-docs.deepseek.com/quick_start/pricing)). Granularity is a **64-token storage unit** (shorter content is never cached). Prefixes persist as discrete units at request boundaries (end of user input, end of model output), on detected common prefixes, and at fixed token intervals; a hit requires a **full match** of a unit. Launch claims: **$0.014/MTok hit vs $0.14 miss** (up to 90% savings, ">50% on average even without optimization"), and 128K-prompt first-token latency **13s → 500ms**. Current: `deepseek-flash` **$0.003/MTok** off-peak hit vs **$0.15** miss (50×). Eviction is best-effort, hours to days.

**Gemini** ([docs](https://ai.google.dev/gemini-api/docs/caching)): implicit caching is **default-on for all Gemini 2.5+**, stateful and stateless; the Interactions API supports *only* implicit. Minimums: **4,096** tokens for Gemini 3.x, **2,048** for 2.5 Flash/Pro. Hits appear as `usage.total_cached_tokens`.

**Self-hosted**: vLLM APC ([feature](https://docs.vllm.ai/en/stable/features/automatic_prefix_caching/), [design](https://github.com/vllm-project/vllm/blob/main/docs/design/prefix_caching.md)) hashes each block by `hash(parent_hash, block_tokens, extra_hashes)` — extras include LoRA IDs, multimodal image hashes, and **`cache_salt`** for multi-tenant isolation. Only **full blocks** cache; `sha256` is default as of v0.11 (`sha256_cbor` for reproducible cross-environment hashing); eviction is **LRU**. APC reduces only prefill — no gain when decode dominates. SGLang's RadixAttention reported **up to 6.4× higher throughput** ([arXiv:2312.07104](https://arxiv.org/abs/2312.07104)) and ships [session-aware radix cache](https://docs.sglang.io/docs/advanced_features/session_radix_cache) with configurable [eviction](https://docs.sglang.io/docs/advanced_features/radix_eviction_policy). **Routing corollary**: caches are per-replica, so identical prefixes must reach the same worker — Manus: enable prefix caching "and use techniques like session IDs to route requests consistently across distributed workers" ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)).

## 2. What breaks the KV cache, by blast radius

1. **Tool-definition changes** — Anthropic: kills tools+system+messages, the *entire* cache. Manus: definitions serialize near the front, "so any change will invalidate the KV-cache for all subsequent actions and observations."
2. **A front-loaded timestamp** (second-precision worst) — Manus's named archetype: it "lets the model tell you the current time, but it also kills your cache hit rate."
3. **System-prompt edits / web-search or citations toggles** — system cache plus everything after dies; tools cache survives.
4. **Mid-iteration tool add/remove** — Manus: "unless absolutely necessary, avoid dynamically adding or removing tools mid-iteration," for cache reasons *and* because stale references cause schema violations and hallucinated actions. Their fix is masking token logits via response prefill; OpenAI's is `tool_choice: "none"`, `allowed_tools`, or `defer_loading` + tool search. Anthropic's `defer_loading` adds tools *without* breaking cache.
5. **Modifying earlier messages** — Manus: "Make your context append-only." OpenAI: "summarization, compaction, or context truncation can change the prefix and reset cache reuse."
6. **Non-deterministic JSON key ordering** — Manus: unstable serialization key ordering "can silently break the cache."
7. **Images appearing/disappearing anywhere** — invalidates the messages cache regardless of distance from the breakpoint.
8. **`tool_choice`, thinking params, `effort`** — messages cache only; effort set explicitly to the model default does not invalidate.
9. **Compaction / context editing** — OpenAI: "the first request after compaction may reuse less of the previous cache." Anthropic: tool-result clearing invalidates prefixes; gate it with `clear_at_least`.
10. **Extending a message in place** — OpenAI: the old endpoint is now mid-message and unreusable without an explicit breakpoint there.

## 3. Fresh state every step vs. retrieve on demand

Manus quantifies the asymmetry: "the average input-to-output token ratio is around 100:1," because agent output is a short function call while context grows every step. They call KV-cache hit rate "the single most important metric for a production-stage AI agent," citing Claude Sonnet at $0.30/MTok cached vs $3/MTok uncached (10×). Their remedy is **restorable** compression — drop a web page's content but keep its URL, omit a document but keep its sandbox path — treating the file system as unbounded context.

Anthropic's [effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) recommends the same "just in time" pattern (agents hold paths, queries, links and load data at runtime) while conceding that "runtime exploration is slower than retrieving pre-computed data" — hence a hybrid: CLAUDE.md up front, glob/grep for the rest. The stated static-context ceiling is "the *smallest possible* set of high-signal tokens," since every token depletes a finite attention budget ([context rot](https://research.trychroma.com/context-rot)).

**The cache-miss cliff.** With a **cumulative prefix hash**, a change at token *k* invalidates every hash from *k* onward, and vLLM states APC "only reduces the time of processing the queries (the prefilling phase)." Manus: "even a single-token difference can invalidate the cache from that token onward." **[EXTRAPOLATION]** One changed token at position 0 of a 100K context therefore forces a full 100K-token re-prefill — 1.25× write pricing on all 100K tokens *plus* full prefill TTFT, versus 0.1× for a read. Hence OpenAI's explicit mode charging post-breakpoint content "at the uncached input rate without a cache-write charge."

**[EXTRAPOLATION]** Arithmetic on sourced Anthropic prices (Sonnet 4.6: $3 in / $3.75 write-5m / $0.30 read), 100K static prefix + 2K dynamic suffix, 30 steps. Uncached prefix: 30 × 100K × $3/MTok = **$9.00**. Cached: one write (100K × $3.75 = $0.375) + 29 reads (100K × $0.30 = $0.87) = **$1.25** (~7.2× cheaper, plus TTFT gains). If the 5-minute TTL lapses every step: 30 × $0.375 = **$11.25** — *worse than no caching at all*. That is the strongest argument for the 1-hour TTL on long agent steps.

## 4. Token budget allocation

Anthropic's [multi-agent research system post](https://www.anthropic.com/engineering/multi-agent-research-system) is the richest published guidance. On [BrowseComp](https://openai.com/index/browsecomp/), three factors explained **95%** of performance variance and "**token usage by itself explains 80%**." Multi-agent (Opus 4 lead + Sonnet 4 subagents) beat single-agent Opus 4 by **90.2%** on their internal eval. Cost side: agents use "about **4× more tokens than chat interactions**"; multi-agent systems "about **15× more tokens than chats**." Effort-scaling rules: simple fact-finding = **1 agent, 3–10 tool calls**; direct comparisons = **2–4 subagents, 10–15 calls each**; complex research = **>10 subagents**. Parallelization "cut research time by up to 90%." The LeadResearcher persists its plan to Memory because "if the context window exceeds **200,000 tokens** it will be truncated," and subagents "return only a condensed, distilled summary of their work (**often 1,000–2,000 tokens**)" — Anthropic's explicit subagent-output budget. Subagents should write artifacts to a filesystem and return "lightweight references" rather than piping large outputs through the coordinator.

Compaction thresholds: Claude Code retains the summary "plus the **five most recently accessed files**"; server-side compaction triggers at **150,000** tokens (floor 50,000), SDK compaction at **100,000**. Tuning advice: "start by maximizing recall... then iterate to improve precision." Rewriting a bad MCP tool description cut task completion time by **40%**.

Cognition's [Don't Build Multi-Agents](https://cognition.ai/blog/dont-build-multi-agents) reaches the opposite conclusion: share context and full agent traces, because "actions carry implicit decisions, and conflicting decisions carry bad results" — favoring a single-threaded linear agent plus a fine-tuned compression model. **[EXTRAPOLATION]** Synthesis: parallelism buys tokens and therefore performance when subtasks are genuinely independent and low-coupling, and costs reliability when decisions are coupled — close to Anthropic's own caveat that "most coding tasks involve fewer truly parallelizable tasks than research." OpenAI's [practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) adds the counterweight: maximize a single agent with tools first, splitting into multiple agents only when it "fails to follow instructions or select tools" under complex conditional logic or tool overload.
