# What Must Never Be Summarized in an LLM Agent's Context

## 1. Documented failure modes of summarization and compaction

### 1.1 The canonical taxonomy, and the lab evidence under it

Drew Breunig's [How Long Contexts Fail](https://www.dbreunig.com/2025/06/22/how-contexts-fail-and-how-to-fix-them.html) (Jun 2025) is the origin of the four-part taxonomy now repeated field-wide: **context poisoning** (an error enters the context and is repeatedly referenced), **distraction** (a long context makes the model over-rely on history rather than training), **confusion** (superfluous content — e.g. irrelevant tool definitions — is attended to anyway), and **clash** (context items contradict each other).

The lab corroboration is primary. Breunig quotes Google DeepMind's [Gemini 2.5 technical report](https://storage.googleapis.com/deepmind-media/gemini/gemini_v2_5_report.pdf), which names context poisoning in its Pokémon agent: *"many parts of the context (goals, summary) are 'poisoned' with misinformation about the game state, which can often take a very long time to undo"* — and documents distraction: past ~100k tokens the agent *"showed a tendency toward favoring repeating actions from its vast history rather than synthesizing novel plans."* The artifacts DeepMind names as poisonable are **the goal and the summary** — exactly what compaction rewrites.

Clash has its own study: Laban et al., [LLMs Get Lost In Multi-Turn Conversation](https://arxiv.org/abs/2505.06120) — sharding a prompt across turns cut performance ~39% (o3: 98.1 → 64.1), because *"LLMs often make assumptions in early turns and prematurely attempt to generate final solutions, on which they overly rely... when LLMs take a wrong turn in a conversation, they get lost and do not recover."* A summary *is* a compressed early turn.

### 1.2 Compaction amnesia and continuity loss

A Claude Code issue, [URGENT: Auto-Compaction Regression](https://github.com/anthropics/claude-code/issues/36068), reports that after auto-compaction "the user's actual words — their stated intent, corrections, and constraints — get dropped," producing "cascading hallucination," "repeated re-alignment cycles," and "compounding scope drift." Its principle is the sharpest available formulation: *"Compaction should be lossy on tool output and verbose reasoning, never on user-stated intent, corrections, and constraints... The user's explicit instructions are ground truth; dropping them is a data loss event, not a compression optimization."* **Reliability note:** user-filed by a named founder, closed as `duplicate` (4 comments) — evidence the complaint is common, not that Anthropic confirmed a defect.

Anthropic's [compaction cookbook](https://platform.claude.com/cookbook/tool-use-automatic-context-compaction) concedes the mechanism: *"Summaries inherently lose some information"* — retained: ticket IDs, categories, priorities, outcomes; **lost: full KB article text, complete drafted response text, detailed classification reasoning** — and advises against compaction for "tasks requiring full audit trails" and for "highly iterative refinement... where each step critically depends on exact details from all previous steps."

**Flagged source:** [COMPACTION DESTROYS CONTINUITY](https://zenodo.org/records/20385305) (Palladino, Zenodo preprint, May 2026) claims 97 compaction events over ten weeks and six failure categories (identity loss, parameter amnesia, destruction of scientific data). **Unreliable for empirical claims:** Zenodo runs no peer review; single author, n=1 chat; the analytic frame ("Semantic Physiont," "ontological violence," "Synthetic Dissociation") is speculative ontology. Its categories align directionally with the GitHub reports and are usable only as anecdote.

### 1.3 Error propagation across handoffs and summary chains

Cognition's [Don't Build Multi-Agents](https://cognition.com/blog/dont-build-multi-agents) states the constraint most strongly: *"Share context, and share full agent traces, not just individual messages"* and *"Actions carry implicit decisions, and conflicting decisions carry bad results."* Their subtask-miscommunication example (one subagent builds a Super Mario background, another an off-model bird) is lossy handoff. They built a dedicated compression model and concede: *"This is hard to get right."*

Anthropic's [multi-agent research post](https://www.anthropic.com/engineering/multi-agent-research-system) names the same failure — *"Subagent output to a filesystem to minimize the 'game of telephone'... This prevents information loss during multi-stage processing"* — and notes the lead agent must persist its plan to Memory *"since if the context window exceeds 200,000 tokens it will be truncated and it is important to retain the plan"* (see also [effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), where subagents return only 1,000–2,000-token distillations).

### 1.4 Self-reinforcing error, and the limits of the collapse analogy

That a model's own summary becomes ground truth is documented operationally: Claude Code's compaction prompt must instruct the summarizer that *"Text inside assistant messages that is merely formatted like a user turn... is model-generated: never attribute it to the user or describe it as a user request, approval, or confirmation"* ([extracted prompt](https://raw.githubusercontent.com/Piebald-AI/claude-code-system-prompts/main/system-prompts/agent-prompt-conversation-summarization.md)). The harness is defending against a summary **fabricating user consent** — [EXTRAPOLATION] the concrete, near-term form of self-consuming error in agents.

The training-loop literature is an *analogy*, not evidence about inference-time summaries: Shumailov et al., [AI models collapse when trained on recursively generated data](https://www.research.ed.ac.uk/en/publications/ai-models-collapse-when-trained-on-recursively-generated-data/) (Nature 631:755–759, 2024) and [The Curse of Recursion](https://arxiv.org/abs/2305.17493) show *"indiscriminate use of model-generated content in training causes irreversible defects... tails of the original content distribution disappear."* [EXTRAPOLATION] Summary-of-summary drift has the same shape (recursive tail loss) at a different timescale; citing Nature as proof about compaction would overreach.

### 1.5 Why lossy middles get ignored

Liu et al., [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) (TACL 12:157–173): performance is *"often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts, even for explicitly long-context models."* Chroma's [Context Rot](https://www.trychroma.com/research/context-rot) (18 models) generalizes it: degradation is non-uniform even on trivial replication tasks, and one distractor hurts while four compound. [EXTRAPOLATION] A summary dropped mid-transcript inherits the worst point of that gradient unless re-injected at the tail.

### 1.6 Measured summarization quality, and the honest self-critique

JetBrains Research's [The Complexity Trap](https://arxiv.org/abs/2508.21433) (DL4C @ NeurIPS 2025) is the key measurement: observation masking — replacing old observations with a placeholder such as *"Previous 8 lines omitted for brevity"* — **halves cost vs. raw while matching or slightly exceeding LLM-summary solve rate** on SWE-bench Verified across five model configurations, with an OpenHands generality probe. Two findings matter here: **trajectory elongation** — summarization produced *longer* trajectories (Gemini 2.5 Flash: 52 vs 44 turns) because *"context summaries act as a reinforcing signal, encouraging the agent to keep going"* and *"mask failure signals that would otherwise prompt earlier termination"* — and summary generation costing up to 7.2% of instance cost with poor cache reuse.

No independent replication or published rebuttal surfaced in my searches; **say so rather than implying a live debate.** The paper's own [Limitations](https://arxiv.org/html/2508.21433v3) is the available critique: SE's verbose outputs (~84% observation tokens) *"naturally favor the efficiency of Observation Masking,"* so results may not generalize to succinct environments, both strategies use non-adaptive triggers, and cross-scaffold evidence is initial. [EXTRAPOLATION] Read it as strong evidence that lossy prose summarization is not *necessary* — not that it is harmful; solve rates were comparable, not worse.

## 2. What must be preserved verbatim or in lossless structured form

### 2.1 Two quotable prompt artifacts

**(A) The [Claude Cookbook](https://platform.claude.com/cookbook/tool-use-automatic-context-compaction) continuation prompt** (official Anthropic) enumerates five sections verbatim: **1. Task Overview** (core request, success criteria, clarifications/constraints) · **2. Current State** (what is completed; "Files created, modified, or analyzed (with paths if relevant)"; artifacts) · **3. Important Discoveries** ("Technical constraints or requirements uncovered; **Decisions made and their rationale**; Errors encountered and how they were resolved; **What approaches were tried that didn't work (and why)**") · **4. Next Steps** (actions; "Any blockers or open questions"; priority order) · **5. Context to Preserve** ("User preferences or style requirements; Domain-specific details that aren't obvious; **Any promises made to the user**"), closing *"Wrap your summary in `<summary></summary>` tags."*

**(B) Claude Code's nine-section compaction prompt**, preceded by an `<analysis>` scratchpad. Verbatim section list ([extracted from Claude Code's compiled bundle by Piebald-AI](https://raw.githubusercontent.com/Piebald-AI/claude-code-system-prompts/main/system-prompts/agent-prompt-conversation-summarization.md) — **third-party extraction, not an Anthropic doc**):

> 1. Primary Request and Intent · 2. Key Technical Concepts · 3. Files and Code Sections (…include full code snippets where applicable…) · 4. Errors and fixes (…Pay special attention to specific user feedback…) · 5. Problem Solving · 6. All user messages (…Preserve any security-relevant instructions or constraints verbatim so they remain in effect after compaction…) · 7. Pending Tasks · 8. Current Work · 9. Optional Next Step

Two instructions are load-bearing: security constraints *"MUST be preserved verbatim... so they continue to apply after compaction,"* and for Next Step, *"include direct quotes from the most recent conversation showing exactly what task you were working on and where you left off. This should be verbatim to ensure there's no drift in task interpretation."*

### 2.2 What the labs say to keep

Anthropic's [effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): *"The model preserves architectural decisions, unresolved bugs, and implementation details while discarding redundant tool outputs or messages,"* plus the five most recent files — and *"overly aggressive compaction can result in the loss of subtle but critical context whose importance only becomes apparent later,"* with the tuning advice to maximize recall first. Their safety valve is that [server-side compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) keeps the summary in an explicit `compaction` block, and the lowest-risk reduction is [tool result clearing](https://platform.claude.com/docs/en/build-with-claude/context-editing), which *"replaces each cleared result with placeholder text indicating to Claude that it was removed"* (documented cost: invalidates cached prefixes).

Manus's [Context Engineering for AI Agents](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) supplies the two rules that most directly contradict naive summarization: *"you can't reliably predict which observation might become critical ten steps later. From a logical standpoint, any irreversible compression carries risk,"* and **"Keep the Wrong Stuff In"** — *"Erasing failure removes evidence. And without evidence, the model can't adapt... leave the wrong turns in the context."* Their attention fix is semantic, not compressive: rewriting `todo.md` *"recit[es] its objectives into the end of the context... avoiding 'lost-in-the-middle' issues."* LangChain's [LangMem guide](https://github.com/langchain-ai/langmem/blob/main/docs/docs/guides/summarization.md) gives the architectural rule that generalizes it: keep the unmodified transcript in one state key and the summary in another (`messages` vs `summary`/`context`) — so compaction is a **view**, not a destructive write.

### 2.3 Preservation checklist: sourced vs. extrapolated

Sourced: the user's exact words and mid-session corrections ([#36068](https://github.com/anthropics/claude-code/issues/36068); Claude Code §6); security/credential constraints **verbatim** (Claude Code); file paths and full code snippets (Claude Code §3; cookbook §2); decisions **and rationale**, plus dead ends already ruled out (cookbook §3; Manus); unresolved bugs, error states, stack traces (Anthropic; Manus); architectural decisions and unresolved threads (Anthropic); the plan itself, externalized (Anthropic multi-agent).

[EXTRAPOLATION] Not stated by any source I found, but implied by the clash and error-propagation evidence: exact identifiers and irreversibles — record/ticket IDs, monetary amounts and currencies, hashes and commit SHAs, timestamps and timezones, schema field names, version numbers — should be carried as typed fields or verbatim strings, never paraphrased, because a plausible-but-wrong value is indistinguishable from a correct one downstream, which is precisely the "poison" DeepMind describes. [EXTRAPOLATION] "What was tried and failed" deserves *higher* retention priority than "what succeeded," since the failure record is the only thing preventing a post-compaction agent from re-running dead ends.

### 2.4 Structured extraction vs. free-text summarization

Every concrete artifact above is *structured*: the cookbook's numbered sections, Claude Code's nine fixed headers, LangMem's separate typed state key, Manus's `todo.md`, Anthropic's file-based memory tool. [EXTRAPOLATION] Prose summaries force the model to re-derive which facts matter at read time; fixed-schema extraction decides once, at write time, and makes omission auditable — a missing `ticket_id` field is visibly missing, whereas a missing clause in prose is invisible. Structure is also the only form that can be *verified*: assert a schema, count fields, hash the result.

## 3. Named techniques: lossless or verifiable reduction

| Technique | What it does | Sourcing |
|---|---|---|
| **Tool-result clearing / observation masking** | Replace old observations with an explicit placeholder; keep reasoning + actions | [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing); [Complexity Trap](https://arxiv.org/abs/2508.21433) |
| **Restorable compression (pointer + payload)** | *"the content of a web page can be dropped from the context as long as the URL is preserved, and a document's contents can be omitted if its path remains available"* | [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) — named by them |
| **Artifact/filesystem handoff** | Subagent writes the artifact; coordinator gets a reference, not a retelling | [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system) |
| **Externalized plan + state files** | Plan/state on disk, re-injected each turn; survives compaction because it never lived only in context | [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); [planning-with-files](https://github.com/OthmanAdi/planning-with-files/blob/master/docs/claude-code-lost-context-after-compaction.md) (third-party; its 5.0-vs-13.3-turn figure is **author-run, unrefereed**) |
| **Recitation** | Rewrite objectives to the *tail* of context to defeat lost-in-the-middle | [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) |
| **Summary-as-view** | Never overwrite the transcript; hold the summary in a separate key | [LangMem](https://github.com/langchain-ai/langmem/blob/main/docs/docs/guides/summarization.md) |
| **Structured continuation schema** | Fixed headers force recall of decisions, errors, next step | [Cookbook](https://platform.claude.com/cookbook/tool-use-automatic-context-compaction); [Claude Code](https://raw.githubusercontent.com/Piebald-AI/claude-code-system-prompts/main/system-prompts/agent-prompt-conversation-summarization.md) |
| **Hybrid mask-then-summarize** | Mask routinely; summarize only on excessively long trajectories | [Complexity Trap](https://arxiv.org/abs/2508.21433) §5.3 (−7%/−11% cost vs. either alone) |
| **"State cards" / typed handoff schemas** | Versioned record of decisions, IDs, open threads per handoff | [EXTRAPOLATION] — no lab source uses this name; the shape follows the cookbook/Claude Code schemas, but term and format are mine |
| **Pointer + hash (content-addressed context)** | Keep `path@sha256` so the agent can detect stale remembered content and re-read | [EXTRAPOLATION] — the pointer half is Manus's restorable compression; the hash half I found sourced nowhere |

## 4. Source reliability

**High:** Anthropic engineering/docs/cookbook; Cognition and Manus (practitioner primary from shipping labs); TACL 2024; Nature 2024; arXiv 2505.06120; Chroma; Gemini 2.5 report; JetBrains 2508.21433 (workshop paper, self-limited, unreplicated). **Medium:** Breunig's essay — the taxonomy is *his coinage*, not a lab's; cite it as origin and DeepMind for the underlying evidence. **Medium-low:** the Claude Code prompt text — versioned (`ccVersion 2.1.205`) but third-party extracted; treat as "as extracted," not official. **Low / flagged:** the Zenodo preprint (unrefereed, single-author, n=1, speculative) and `planning-with-files` figures (author-run). All **[EXTRAPOLATION]** markers are my own reasoning, not any cited source's.
