## 为什么必须是**进程外** watchdog

`SIGSTOP` 只暂停，不触发任何清理：进程内的心跳守卫此时**自己也停了**，撤单不可能由它完成。
所以真正的撤单只能由独立进程读同一个 SQLite（WAL）后执行（plan §6.3）。

## 流程

1. 子进程打开临时库，写一条 heartbeat 后 `SIGSTOP` 自己（`State: T`，非退出）；
2. 父进程用**同一个库**构造 `HeartbeatStore` + `ExternalWatchdog`，
   broker 用一个把挂单写进 JSON 文件的假实现，`intervalMs` 取小值；
3. 父进程跑 `checkOnce()`：判定 stale → `cancelAll()` 成功 → 才写 `halted=1`；
4. 再跑一次 `checkOnce()` 验证幂等。

## 语义要点

- **撤单成功才置 halted**：若 `cancelAll()` 抛错，watchdog 只发 critical 告警并**保持
  unhalted**，下一轮重试 —— 绝不能出现"记了 halted 但单还挂着"的假安全状态。
- **没有 heartbeat 行也按 stale 处理**（fail-closed）：数据库缺行本身是异常，
  不能因为"查不到"就当成"很健康"。
- 撤单只发生在第一次；恢复必须人工 `/resume`（plan §6.3）。
